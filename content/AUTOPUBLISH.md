# 自動投稿(週3回)の運用ルール

週3回(月・水・金 10:00 JST)、ブログ記事を自動で公開する。オーナーの承認は不要(2026-09-24 オーナー指示)。
ただし、下の品質ルールを満たさない記事は公開しない。

## 仕組み
- 記事 = `content/articles/*.html`(先頭に `<!--meta id/title/category/publishAt-->`)
- `node scripts/build-posts.js --strict` で検証しつつ `api/_posts-static.json` を生成し、トップページ(`index.html`)の新着記事リンクも更新 → コミット → デプロイ
- `publishAt` の日(日本時間10:00)になると、サイトに自動で表示される。それまでは非公開(URLも404)。
- 公開日の朝9時(UTC 0時)に、その日公開された記事を検索エンジンへ自動通知(IndexNow)。
- 取り下げたい記事: ファイルを削除(または publishAt を遠い未来に変更)→ 再生成 → デプロイ。

## 毎週の作業(自動実行タスク: 毎週日曜の夜)
1. `git pull` で最新にし、`content/articles/` の最後の publishAt を確認する。
2. 公開予定が **14日先まで** 埋まるように、月・水・金の枠に記事を追加する(通常は週3本)。
3. テーマは `content/topics.md` の「優先リスト」を、P1から順に選ぶ(キーワード・見出し案・事実確認の点が書いてある。見出し案は参考で、より良い構成にしてよい)。優先リストを使い切ったら「その他のネタ」から選ぶ。使ったテーマは「使用済み」に移す。**事実確認の点は、必ず公式情報で確認してから書く。**
4. 時事性のある事実(料金・制度・統計・機能)は、必ず WebSearch で公式情報を確認し、確認日を意識して書く。確認できないことは書かない。
5. `node scripts/build-posts.js --strict` が通ることを確認する(通らなければ直す。無理に通さない)。
6. `git add content api index.html` して、`content: 記事を追加(公開予定 MM/DD・MM/DD・MM/DD)` でコミット → 本番へデプロイ。※ビルドで `index.html` の新着記事リンクも更新されるため、`index.html` も必ずコミットする。
7. 結果を `AI経営.RAIZON/ops/weekly/` に1行で記録する(公開予定の記事名と日付)。

## 品質ルール(必須)
- 対象: BtoCの店舗・サービス事業者(美容・サロン、整体・フィットネス、飲食、小売、観光・体験、学習塾など)で、LINE公式アカウント・予約・シフト管理・業務のデジタル化を検討している人。
- 1記事1テーマ。本文は1,500〜2,500字目安。冒頭の段落(60〜120字)に答えと主要キーワードを入れる(検索結果の説明文になる)。
- タイトルは30〜40字。「｜」で区切り、主要キーワードを前半に。
- 見出し(h2/h3)、箇条書き、「よくある質問」(h2 の下に h3=質問・p=回答)、「ご相談はお問い合わせフォームから」(`<a href="/#contact">お問い合わせフォームから相談する</a>`。LINEは補助)を必ず入れる。
- 他の記事への内部リンクを2つ以上入れる(`/blog/記事id`)。存在するidだけ。
- **内部リンク先の記事の公開日は、リンク元の記事の公開日以前にすること**(未公開の記事へのリンクは、公開直後にリンク切れ=404になる)。検証スクリプトが自動で確認する。
- **書いてはいけないこと:** 根拠のない数字・効果の断定(〇%増、〇倍、確実に、必ず、絶対、No.1、県内一など)/他社の批判や断定的な比較/お客様の名前・写真(許可なし)/法律・税務・医療の断定的な助言/誇大な表現。
- 自社(RAIZON)の記載は事実だけ: 初期費用0円、最低契約期間なし、LINE利用料はお客様負担、月額プランは税込5,500円(BASIC)/10,780円(STANDARD・ホームページ作成相談を含む)/21,780円(PREMIUM)、買い切り149,600円〜(価格が変わったら、この一文も更新する)。
- 同じ内容の焼き直しをしない。既存記事と、タイトル・検索意図が重ならないこと。

## 停止・見直し
- オーナーが「止めて」と言ったら、自動実行タスクを停止し、予約分は publishAt を未来にずらす。
- 4週間ごとに、公開した記事の数と、検索経由の問い合わせ(LINE追加・相談)の数を `ops/kpi.md` に記録し、テーマを見直す。
